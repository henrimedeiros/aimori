# Design-Review: Code und Geheimnisse, Ausweise und Rechnungen in Bildern (16.10.2026)

Urteil Sicherheits-Review vor dem Bauen: **FREIGEGEBEN MIT AUFLAGEN**. Vorhaben: eingefügten Code erkennen und darin zusätzlich interne Hosts und zufällig wirkende Zeichenfolgen finden, im Dialog die Zeile nennen; Bildtext zusätzlich an die lokale KI und an eine Dokumentart-Erkennung (Ausweis, Rechnung) geben. Keine neue Abhängigkeit, kein Netz, keine neue Berechtigung, nichts gespeichert. Antwort auf die Frage nach der Standard-Aktion: **doc_identity = block** (Ausweisdaten erleichtern Identitätsdiebstahl, ein Fehlalarm kostet einen Klick), **doc_invoice = warn**.

Abweichung vom Vorhaben: `isCode`/`linesOf` liegen nicht in einer neuen Datei `engine/code.js`, sondern als `DLX.code` in `engine/packs-secrets.js` (wird überall geladen, wo die Detektoren laufen; keine weitere Ladeliste). Die Typen `doc_identity`/`doc_invoice` sind als abgeleitetes Paket `bild` in `engine/bild.js` registriert (wie Paket `ki` in `engine/ki.js`); `bild.js` ist deshalb zusätzlich in `ui/dialog.html`, `ui/options.html` und `ui/wissen.html` geladen (Namen der Typen). Im Offscreen-Dokument (`ui/ocr.html`, ohne Engine) entfällt die Registrierung.

Restrisiken (übernommen in die Doku): Bildprüfung ist „nach bestem Bemühen“ (gedrehte, unscharfe, kleine oder handschriftliche Dokumente können durchrutschen); kurze Code-Schnipsel werden evtl. nicht als Code erkannt (dann laufen nur die bisherigen Detektoren); Fehlalarme bei den neuen Typen sind dezent bzw. per Richtlinie abschaltbar; Zeilennummern bleiben lokal im Dialog.
