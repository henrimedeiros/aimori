# Design-Review: Muster mitmachen (16.10.2026)

Vorhaben (16.10.2026): Gemeinschafts-Muster-Katalog als versionierte, signaturgeprüfte Datei im Repo (Format, JSON-Schema, synthetische Positiv/Negativ-Tests je Muster), Beiträge über Pull-Requests mit automatischer Prüfung (Schema, Tests, Fehlalarm-Rate, ReDoS), neue Muster nur mit Erweiterungs-Updates, eigene Muster der Organisation per Richtlinie. Keine Abhängigkeiten, kein Netz aus der Erweiterung.

Urteil Sicherheits-Review (vor dem Bauen, 16.10.2026): **freigegeben mit Auflagen**.

| Nr. | Auflage | Umsetzung |
|---|---|---|
| 1 | Vertrauensanker ausserhalb des PR-Bereichs: nur fest in `scripts/muster.mjs` eingetragene Fingerabdrücke; CI bricht ab bei Änderungen an `muster/schluessel/`, `katalog.sig`, `CODEOWNERS`, `.github/`, `scripts/` | `VERTRAUT` in `scripts/muster.mjs`, `pruefeSignatur()` ignoriert fremde `.pub`; Schritt „Geschützte Pfade“ in `.github/workflows/muster.yml` (zusätzlich Muster-Engine); `.github/CODEOWNERS`; Tests „fremder Schlüssel“, „CI-Workflow“ |
| 2 | Einweg-Entwicklungsschlüssel als `dev`, Release nur mit dem Release-Schlüssel der Maintainer; privater Teil nie im Cache/Git, Löschung nachweisen | `art: 'dev'`, `bauen --release` verlangt `release` (Test); privater Schlüssel existierte nur im Speicher des Signier-Prozesses (nie auf Platte geschrieben); Test „kein privater Schlüssel im Repo“ |
| 3 | Release-Schlüssel nur im eigenen Terminal, ausserhalb von Repos, Passphrase ohne Echo über stdin, PKCS#8 mit AES-256 + scrypt; automatisierte Abläufe signieren nie mit echtem Schlüssel | `schluessel`/`signieren` in `scripts/muster.mjs` (`liesGeheimnis` ohne Echo, `ausserhalbRepos`, `verschluessele` scrypt N=2^17 + AES-256-GCM über PKCS#8); Doku `docs/muster-mitmachen.md` |
| 4 | CI: Prüfer aus `base.sha`, aus dem PR nur `katalog.json`; kein Token in der Git-Konfiguration (öffentlich ohne Token); keine Secrets, Cache, Artefakte; `timeout-minutes`, `concurrency` | `.github/workflows/muster.yml` (nur `run`-Schritte, `git fetch` ohne Anmeldung, `git show "$HEAD_SHA:muster/katalog.json"`, `permissions: contents: read`, Trigger `pull_request`); Test „CI-Workflow“ |
| 5 | safeRegex: `{n,m}` nur bis 64; benachbarte variable Quantoren nur mit Produktgrenze; Katalog-Flags nur `i`/`u` | `extension/engine/muster.js` `safeRegex` (MAX_Q 64, MAX_COST 1000, Flags `^(?:i?u?)$`); Tests „safeRegex …“ |
| 6 | Lasttest aus den Zeichen des Musters; zur Laufzeit Höchstlänge oder Stückelung, Budget zwischen den Mustern | Pipeline `lastEingaben()` (Testwert, Teilstücke, Einzelzeichen auf 100 000 Zeichen); Engine `windows()` in `engine.js` (2048 Zeichen + längster Treffer, Budget zwischen Fenstern); Tests „Lasttest“, „Fenster-Scan … dieselben Treffer“ |
| 7 | Bündel ohne `tests`, `lizenz`, `quelle` | `bundleText()` nur Laufzeitfelder; Test „Bundle enthält nur Laufzeitfelder“ |
| 8 | Namen ≤ 60, nur druckbare Zeichen (auch `ctx`), Darstellung nur per `textContent`, Id-Kollisionen | `textOk()` (`\p{Cc}\p{Cf}\p{Zl}\p{Zp}` verboten); UI nutzt bestehende `typeName()` + `textContent`/`h()`; Kollision Katalog untereinander und mit eingebauten Typen (`id_kollision`, `doppelt_zu_*`) |
| 9 | Testdaten nur offiziell dokumentiert oder generiert; Pflicht-Haken in PR-Vorlage und CONTRIBUTING; Kunden-Blockliste lokal | `synthetischOk()` (Domains nur example/.test/.invalid oder Host aus dem Muster, IPv4 nur Doku-Bereiche); `.github/PULL_REQUEST_TEMPLATE.md`, `CONTRIBUTING.md`; Maintainer prüft lokal mit der Kunden-Blockliste vor dem Signieren |
| 10 | `customPatterns` nur aus `storage.managed`, `action` nicht schwächer als Standard, `cat` fest, `context` ≤ 20 × 40, keine Texte in Logs, Test Benutzerwert ignoriert | `policy.js` Fall `customPatterns` (`user` → verworfen), `compileOrg()` (Aktionen `warn`/`redact`/`block`, feste Schlüssel), Anzeige generisch `org_pattern`; Tests „Benutzerwert wird ignoriert“, „ungültiger Eintrag verwirft das ganze Feld“ |
| 11 | Netzwerk-Sperrtest umfasst `muster.js`; kein `fetch`/`XMLHttpRequest`/`eval`/`new Function`/`importScripts(` mit dynamischem Argument in `extension/` | `tests/quelltext.test.mjs` prüft alle `extension/**/*.js` (inkl. `muster.js`, `packs-community.js`), neue Regel „importScripts dynamisch“ |
| 12 | Veröffentlichung (Repo, Remote, Store-Update) nur mit Freigabe der Maintainer; Doku ohne Firmenbezug | Doku ohne Firmenbezug |

Restrisiken: ReDoS trotz statischer Prüfung (mittel; Auflagen 5/6 + menschliches Review vor jeder Signatur); Fehlalarme eines standardmässig aktiven Gemeinschafts-Musters (mittel; Fehlalarm-Ziel als CI-Pflicht, Paket abwählbar); Verlust/Diebstahl des Release-Schlüssels (tief; Passphrase, Ablage ausserhalb der Repos, Rotation über `VERTRAUT` nur per Update); zu breite Admin-Muster (tief; safeRegex, 50 Einträge, generische Anzeige).
